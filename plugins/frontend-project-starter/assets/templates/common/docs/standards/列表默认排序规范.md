# 列表默认排序规范

## 目标

列表默认排序应该帮助用户优先看到当前最需要处理或最新产生的数据，而不是让每个页面随手写一个 `createdAt,desc`。

## 默认规则

- 审核或待办列表：优先展示待处理、进行中、最近更新的记录。
- 申请类列表：优先展示当前用户最近创建、最近提交、或仍可操作的记录。
- 历史归档列表：可按结束时间或更新时间倒序。
- 关联选择器：优先展示可选、有效、未结束的数据，再展示历史数据。

## 禁止事项

- 不要在前端页面里随意覆盖后端已经标准化的排序。
- 不要因为某个字段偶然存在就固定使用它作为所有列表排序。
- 如果排序影响业务链路，必须在接口契约或标准文档中记录原因。
- 不要把默认排序原因写成页面上的说明文案；页面只呈现排序结果，治理原因留在接口契约、标准文档或必要的代码注释里。
