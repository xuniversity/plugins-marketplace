# 表单校验与可中断流程交互规范

## 默认状态

如果项目没有更具体的业务状态契约，申请类记录默认使用：

- `草稿`
- `待审核`
- `审核中`
- `已取消`
- `已驳回`
- `已通过`

## 保存与提交

- `保存` 和 `提交` 默认使用同一字段校验级别，除非需求明确说明保存可跳过必填项。
- 前端掌握足够上下文时，应先在本地拦截字段级错误。
- 后端校验错误必须保留明确提示，不吞掉业务原因。

## 可中断流程

对于 `待审核` 或 `审核中` 的记录，编辑、删除、取消等会终止流程的操作必须：

1. 先提示用户该操作会影响当前流程。
2. 用户确认后终止当前流程。
3. 自动继续用户原本发起的编辑、删除或取消动作。
4. 保持页面状态可恢复，不让用户重新找入口。

## 操作口径

- `已通过` 默认不允许再编辑、取消或删除，除非需求明确声明。
- `已取消` 与 `已驳回` 可以根据业务需要允许删除或重新提交。
- 列表、详情、弹窗中的状态文案必须一致。
