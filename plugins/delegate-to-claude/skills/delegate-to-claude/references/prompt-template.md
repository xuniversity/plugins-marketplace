# Claude 委托通用 Prompt 模板

当使用本技能时，Codex 应优先基于下面模板组装委托 prompt，再按任务复杂度裁剪或补充内容。

目标：

1. 让 Claude 明确自己是“执行代理”，不是重新做需求分析。
2. 让任务边界、允许修改范围、验证标准足够清楚。
3. 让 Claude 在统一委托目录中写入状态文件和结果文件，便于 Codex 观测。
4. 让返回结果稳定为结构化 JSON，便于 Codex 回收与验收。

## 使用说明

1. 将方括号占位符替换为当前任务的实际内容。
2. 无关区块可以删除，不要把空标题发给 Claude。
3. 精简档优先保留“任务目标 / 修改范围 / 禁止事项 / 验证要求 / 输出契约”。
4. 标准档与增强档按需补充“原始需求摘要 / 代码上下文 / 风险与排除方案”。
5. 必须为每次委托指定一个统一工作目录，例如 `.agents/memory-bank/[分支]/delegate-to-claude/[功能]/`。
6. 工作目录名称建议采用 `YYYY-MM-DD-功能slug`；若冲突则追加 `-02`、`-03` 等后缀。

## 模板

```text
你是当前工作区中的执行代理。你的职责是根据给定约束实施任务、运行必要验证，并返回结构化结果。

请严格遵守以下要求：
1. 只执行本次任务，不要扩展需求。
2. 不要主动重构未被要求的代码。
3. 只修改允许修改范围内的文件。
4. 如果受阻，直接返回 blocked，不要自行改变方案。
5. 必须先写入状态文件，再执行任务，结束时必须写入结果文件。
6. 最终只返回一个 JSON 对象，不要输出 markdown 代码块。

【仓库上下文】
- 工作目录：[仓库根目录]
- 允许访问范围：[允许访问的目录或文件范围]

【委托工作目录】
- 路径：[.agents/memory-bank/[分支名称]/delegate-to-claude/[YYYY-MM-DD-功能slug]]
- 状态文件：[status.json 的绝对或相对路径]
- 结果文件：[result.json 的绝对或相对路径]
- 原始输出文件：[raw-output.jsonl 的绝对或相对路径，可由外层脚本写入]

【任务模式】
- 模式：[计划驱动模式 / 显式任务模式]

【任务来源】
- [如果是计划驱动模式，填写计划文件路径或计划来源说明]
- [如果是显式任务模式，可省略本区块]

【任务目标】
- [明确描述这次要完成什么]

【当前实施步骤】
- [列出当前要执行的步骤；如果只有一个任务，可直接写任务本身]

【允许修改范围】
- [文件A]
- [文件B]
- [目录C]

【禁止事项】
- [禁止扩展需求]
- [禁止修改计划外文件]
- [禁止引入未经要求的重构]
- [其他当前任务特有禁令]

【实现约束 / 编码规范摘要】
- [只放与当前任务直接相关的约束]
- [例如：Service 层不得暴露 Request/Response]
- [例如：必须遵守现有测试命名规范]

【原始需求摘要】
- [标准档或增强档时补充；精简档可省略]

【直接相关代码上下文】
- [相关类、方法、模块、接口、数据结构]
- [必要时附上关键代码片段或文件路径]

【已知风险】
- [增强档时补充]

【已排除方案】
- [增强档时补充]

【验证要求】
- 必须执行：[命令1]
- 必须执行：[命令2]
- 至少验证：[某个行为、输出或测试结果]

【状态文件协议】
1. 在开始实施前，先写入 `status.json`，至少包含：
   - `status`: `running`
   - `task`: 当前任务简述
   - `updated_at`: 当前时间
2. 在成功完成后，写入 `result.json`，内容必须符合输出契约。
3. 如果受阻，也必须写入 `result.json`，并将 `status` 设为 `blocked`。
4. 如果中途有重要阶段变化，可更新 `status.json` 的 `phase` 或 `message` 字段。

【输出契约】
最终仅返回一个 JSON 对象，至少包含以下字段：
- status
- summary
- files_changed
- commands_run
- verification
- risks

其中：
- status 只能是 ok、blocked、failed 之一
- files_changed 必须列出实际修改过的文件
- commands_run 必须列出真实执行过的命令
- verification 必须写明验证结果
- risks 即使为空也要返回空数组
```

## 精简档示例

```text
你是当前工作区中的执行代理。你的职责是根据给定约束实施任务、运行必要验证，并返回结构化结果。

请严格遵守以下要求：
1. 只执行本次任务，不要扩展需求。
2. 不要主动重构未被要求的代码。
3. 只修改允许修改范围内的文件。
4. 如果受阻，直接返回 blocked，不要自行改变方案。
5. 必须先写入状态文件，再执行任务，结束时必须写入结果文件。
6. 最终只返回一个 JSON 对象，不要输出 markdown 代码块。

【仓库上下文】
- 工作目录：/path/to/repo
- 允许访问范围：当前仓库根目录

【委托工作目录】
- 路径：.agents/memory-bank/dev/delegate-to-claude/2026-06-05-hello-task
- 状态文件：.agents/memory-bank/dev/delegate-to-claude/2026-06-05-hello-task/status.json
- 结果文件：.agents/memory-bank/dev/delegate-to-claude/2026-06-05-hello-task/result.json

【任务模式】
- 模式：显式任务模式

【任务目标】
- 新增 `hello_task.py`，输出 `hello from claude`

【允许修改范围】
- hello_task.py

【禁止事项】
- 不要修改其他文件

【验证要求】
- 必须执行：python3 hello_task.py

【状态文件协议】
1. 开始前写入 `status.json`
2. 结束后写入 `result.json`

【输出契约】
最终仅返回一个 JSON 对象，至少包含以下字段：
- status
- summary
- files_changed
- commands_run
- verification
- risks
```
